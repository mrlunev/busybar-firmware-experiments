| Владелец | Что | Почему срочно |

| docs.busy.app | widget-with-ai: `"font": "big"` в пяти примерах; допустимы `tiny`, `small`, `normal`, `condensed`, `bold`, `large`, `extra_large`, `global`, `superscript`. Проверено. Там же `°C`, хотя текст принимает только печатный ASCII. | скопированный пример BUSY Bar отклонит |
| docs.busy.app | JS apps, build, manage-apps и FAQ пишут, что каталога нет или он «скоро». | хакатон на этих страницах |

### Важно

- **busy-tools:** помощник настроек `loadValues()` читает `globalThis.Settings`, которого нет, и молча отдаёт `null`.
  Рабочий способ, `GET /api/apps/settings?app_id=<id>`, не описан ни в одном документе пути с BUSY Bar.
  Эмулятор это обходит, BUSY Bar нет.
- **busy-tools:** ни слова об известных ошибках на Windows (номера из нашего черновика `busy-tools-issues.md`; на GitHub
  они не заведены). Строка README с `--addr 127.0.0.1:8640` на Windows не работает из-за одной из них. `busy-cli --help` показывает устаревшую строку `build`.
- **Прошивка:** `applications_js/AGENTS.md` просит прочитать `AGENTS.md` busy-tools; такого файла нет (проверено,
  404). Обещанные ограничения `fetch` в «JavaScript Applications» не описаны. Пример на чистом JS нарушает
  правила соседнего документа: `127.0.0.1` вместо `localhost`, снятие обработчика внутри него же, `"debug": true`.
- **busylib-ts:** README на GitHub описывает `1.0.0-rc.1` (тег `next`: `displayDraw`, `BusyBarAppClient`), а
  ставится `0.21.1` (`latest`: `DisplayDraw`). Проверено по npm. Агент, читающий README, напишет код, который не
  соберётся.
- **docs.busy.app:** внутренние ссылки в `.md` и `llms-full.txt` вида `docId:...` (244 штуки) агенту не открыть.
  Где лежит OpenAPI, страницы говорят по-разному; публичный адрес `api.busy.app/busybar/openapi.yaml?Name=<версия>`
  не указан нигде. Иконки и картинки отдаются по подписанным ссылкам, которые без браузера отвечают 403.
- **Каталог:** CONTRIBUTING запрещает ссылки на файлы, а его же таблица, проверка и пример принимают
  `description: "@README.md"`. Схема мягче, чем CI.

## 3. Что изменилось в start.txt

- Проверка по USB идёт через `/api/status/firmware`: сразу видно и наличие BUSY Bar, и версию прошивки.
- Новая строка «Отправить приложение в каталог»: `AGENTS.md` и `CONTRIBUTING.md` каталога. Раньше ни один путь
  туда не вёл.
- Для виджетов первым идёт `AGENTS.md` busylib-py: это лучший документ для агентов на этом пути. Страницы docs
  остаются как пошаговый пример.
- Новый раздел «When sources disagree»: OpenAPI по версии прошивки главнее руководств; эндпоинты зависят от
  версии; npm-пакет `busy-cli` не наш.
- Ссылки на `llms.txt` и на `.md`-версии страниц docs.

Правки в start.txt не заменяют исправления в docs и репозиториях, они только страхуют агента, пока исправлений нет.
